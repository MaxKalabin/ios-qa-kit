# Runbook агента-тестировщика

Ты тестируешь iOS-приложение из `APP_BUNDLE` (`config.env`) на реальном iPhone через `appium-mcp`. Работай сам, без вопросов человеку (он спит); при развилке выбирай разумное значение по умолчанию и записывай выбор одной строкой в отчёт.

## Жёсткие границы
- Открывать и трогать только тестируемое приложение. Любое другое приложение — запрещено. Если чужой диалог или приложение перехватило фокус: нажми Home, перезапусти тестируемое приложение, запиши событие, пропусти шаг.
- Не совершать покупки, не отправлять реальных сообщений, не менять настройки телефона и Apple ID, не удалять данные пользователя. Системные диалоги про оплату/Apple ID/пароль: не трогать, записать, пропустить.
- Не писать в общую исходную таблицу багов (только читать). Пиши только в `out/` и в чистую таблицу агента (см. `OUTPUTS.md`).
- Секреты (пароли, токены) не печатать в отчётах и логах.
- Бюджет прогона: не больше 6 часов и 300 действий на сценарий. При лимите — остановиться и отчитаться.

## 0. Перед стартом (обязательно)
1. `ssh <MAC_USER>@<MAC_HOST> 'zsh ~/ios-qa/mac_health.sh'`. Всё FAIL → `zsh ~/ios-qa/mac_start_stack.sh` и снова health. Не вышло за 2 попытки: отчёт «стенд недоступен», остановиться.
2. Создать `run-id` вида `YYYYMMDD-HHMM`, папки `out/{screenshots,logs,bugs,traffic,checklists,reports}/<YYYY-MM-DD>/<run-id>/`.
3. Убедиться, что `~/ios-qa/out/traffic/RULES.json` отсутствует (чистый трафик).
4. Открыть сессию Appium (параметры в `STACK.md`), `appium_app_lifecycle` — перезапуск приложения. Скриншот главного экрана.

## 1. Цикл проверки одного шага
1. Действие в приложении (`appium_find_element` по accessibility id/label, либо `appium_gesture`/тап по координатам из дерева).
2. `appium_screenshot` + при необходимости `appium_get_page_source`. Сохранить кадр в `out/screenshots/...` под именем `<case>-<step>.png`.
3. Прочитать свежие строки журнала сниффера (`docs/SNIFFER.md`): какие запросы ушли, статусы, тела.
4. Вердикт шага по критериям из чеклиста: `[x]` ок, `[!]` дефект, `[~]` не выполнено/блок, `[?]` нужен человек.
5. Если дефект: оформить баг (см. `OUTPUTS.md`), приложить скрин и кусок трафика, пойти дальше.

## 2. Что проверять
- **Регресс-чеклист** — ваш собственный (формат: `checklists/TEMPLATE.md`). Критерии берёт из чеклиста, не придумывает свои.
- **Ответы API vs приложение**: данные на экране совпадают с `resp_body` соответствующего запроса (названия, рейтинги, количества, порядок).
- **API vs Swagger/OpenAPI** (положите спецификацию в `api/`, она не входит в репозиторий): статусы, обязательные поля, типы. Отклонения — баг API.
- **Подмена** (`docs/SNIFFER.md`): ошибки 500, пустые списки, задержки, отказ сети; приложение не должно падать. Правило удалять после каждого кейса.
- **Крэши, зависания, белые экраны, обрезанный текст, ошибки в `errorlog`-запросах** — всегда баг.
- Сверка UI с макетами (Figma) — по желанию, если дать агенту индекс экранов.

## 3. Правила устойчивости
- После каждого шага, который мог зависнуть, проверять, что приложение на переднем плане (`bundleId` = `APP_BUNDLE`). Нет → перезапуск, запись в лог.
- Не делать больше 3 одинаковых безуспешных попыток подряд; шаг помечается `[~]` с причиной.
- Каждые ~50 действий — проверка `mac_health.sh`.
- Любое действие писать в `out/logs/<...>/actions.log`: время, инструмент, параметры, результат.

## 4. Завершение
1. Удалить `RULES.json` на Mac, убедиться, что трафик снова не меняется.
2. Скопировать журнал сниффера прогона в `out/traffic/...`.
3. Записать чеклист (`checklists/TEMPLATE.md`) и утренний отчёт `out/reports/.../report.md`: что проверено, что упало, баги со ссылками, выбранные значения по умолчанию, проблемы стенда, что не успел.
4. Приложение оставить запущенным на главном экране, телефон не блокировать.

## Если что-то непонятно
Сначала прочитай `STACK.md` и `SNIFFER.md`. Нет ответа — выбери безопасный вариант, запиши «допущение:» в отчёт и иди дальше. Не угадывай секреты и не обходи ограничения.
