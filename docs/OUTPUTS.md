# Выходные данные и баги

Локально агент пишет только в `out/` по схеме `out/<папка>/<YYYY-MM-DD>/<run-id>/...`, папки: `screenshots`, `logs`, `bugs`, `traffic`, `checklists`, `reports`. Папка `out/` не входит в git (скриншоты и трафик могут содержать данные). Синхронизацию куда-либо (облако, таблица) настройте сами.

## Баг
Файл `out/bugs/<дата>/<run-id>/BUG-<NNN>.md` и, по желанию, строка в вашей таблице багов.
Содержание: заголовок (экран + суть), сборка, шаги воспроизведения, ожидаемый и фактический результат, скриншоты, кусок трафика (метод, URL, статус, тело), тип `новый` / `перепроверка`, серьёзность (крэш > блокер > серьёзный > мелкий).
Перед записью нового бага найти дубль по названию и экрану в уже известных багах (только чтение); дубль записывать как `перепроверка` со ссылкой.
Исходную таблицу багов агент не правит: только чтение.

## Чеклист
По `checklists/TEMPLATE.md`. Статусы: `[x]` ок, `[!]` дефект, `[~]` пропущено/блок, `[?]` нужен человек. Для каждого `[!]` — ссылка на скрин и баг.

## Утренний отчёт
`out/reports/<дата>/<run-id>/report.md`: сводка (сколько проверено/упало), список багов, расхождения API со Swagger, проблемы стенда, принятые допущения, что не успели, что нужно от человека.
